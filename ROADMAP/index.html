    Roadmap —— book-to-skill 二次开发三阶段路线¶

    制定日期：2026-10-24 ｜ 维护规则：阶段状态变更与里程碑达成以 commit 更新本文件（docs: 前缀） 背景文档：EVALUATION.md（源码级评估）· DEVELOPMENT.md（改动点清单）· COLLABORATION.md（协作规则）

    阶段一：了解功能 / 架构 / 实现方式 —— 状态：✅ 100%（缺口已闭合，见 docs/testing/2026-10-24-phase1-gap-closure.md）¶

    目标：建立对 book-to-skill 的源码级理解，为设计阶段提供可靠事实基础。

    事项 状态
    全量核心代码评审（book_to_skill/ 4,500+ 行 + parsers 7 格式） ✅
    测试体系分析（65 文件 / 901 测试，全部通过） ✅
    架构梳理（"确定性提取器 + SKILL.md 规格书"两半式） ✅
    实测：依赖检查、提取流程、中文章节检测（"第N章"×4 识别） ✅
    评估报告与二开指南入库 ✅
    缺口 1：SKILL.md Step 3-11 精读（拆章/编译/发布规格） ✅
    缺口 2：tools/evals/ 评测框架实跑 ✅
    缺口 3：docling technical 模式实测（表格/代码 PDF） ✅

    验收标准：三个缺口的实测/精读记录入 docs/testing/，本表全部转 ✅。

    阶段二：二次开发设计 —— 状态：🟨 进行中（P1 RFC 01 技术评审通过，待所有者确认冻结 v0.1）¶

    目标：每个二开方向产出一份轻量 RFC，冻结 v0.1 最小可用范围。

    产出物：docs/design/<NN>-<topic>.md，每份含：动机 / 现状分析（对应源码位置）/ 方案 / 改动点清单 / 测试计划 / 风险与回退。

    方向优先级（评审后可调整）：

    优先级 方向 理由 前置依赖
    P1 中文书籍优化 差异化最大、改动面最小、最独立 无
    P2 独立 CLI 工具 pyproject 打包基础现成 无
    P3 Web/API 服务化 依赖 CLI 层稳定 P2
    P4 自定义输出模板 需吃透 SKILL.md 全文 阶段一缺口 1
    P5 更多输入格式 OCR 可并入 P1 视需求

    验收标准：至少 P1 方向 RFC 评审通过（用户确认），范围冻结，进入阶段三。

    阶段三：开发 —— 状态：⬜ 未开始（依赖阶段二冻结）¶

    目标：按 RFC 逐方向实现，延续上游工程质量。

    每个功能单元的固定循环：

    feat: 实现 → test: 配套测试 → 全量 pytest 通过 → push → docs: 测试记录入库

    质量红线： 1. 无测试不 push（延续上游 901 测试基线，全量绿才推）； 2. bug 修复不重命名变量（协作规则 #7）； 3. 遵守上游隐式契约：失败收敛 ExtractionError、"Trying X... OK" 打印格式、单点复用防漂移（详见 DEVELOPMENT.md 第六节）； 4. 定期 git fetch upstream 评估社区修复是否需要跟入（规则 #6：先评估 revert/merge）。

    验收标准：每方向 v0.1 可用 + 测试覆盖 + 文档入库；CHANGELOG.md 增设"本仓库二开记录"小节登记每次发布。
